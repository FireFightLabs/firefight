---
name: watching
when: The person asks to be told later, such as when a run finishes, a build or deploy starts or succeeds, or a resource comes back, or they just started something that takes a while
tools: [get_resource_map, search_map]
---
1. Find each thing to follow on the map with `get_resource_map` or `search_map`: the repository whose CI run it is, the service whose build or deploy it is. A run the person names by number keeps that number.
2. Plan the steps in the order they happen, one per thing the person asked to hear about. A CI run, a build or a deploy is a step reading run_history with its resource, a name such as release, build or deploy when the resource has several kinds of runs, and the run: when you started it or can identify it (the person gave its number, a tool answer named its id), always pass its id or number, so the watch follows that exact run rather than whichever run of that name starts next. For a code host's CI, run_history with the run is the read, since it brings the run's jobs. Set report_start on a step when they asked to hear when it starts.
3. Anything else is "keep checking X until Y": a step with any read you hold, and the condition in plain words as goal, such as every instance of web runs the new version, or the error rate stays under 1% for ten minutes. It is judged on each reading. Add done_when or failed_when when words its answer would hold decide it. A resource coming back or settling reads resource_status or another capability. Anything run_history does not hold, such as a provider's workflow run when its history only lists builds, is a step naming a read tool you hold as tool, with its arguments, such as the provider's API request with method GET for that one run's address by its id (workflows/release/runs/<id>), never a list of recent runs. Find the address in the provider's skill and guides or with search_docs before the web, and try the read once yourself before you start the watch, so you know it shows the thing. A tool that can also change things only reads in a watch.
4. Pass minutes only when the person asked for how long to watch, at most a day. When run history cannot show how long it takes, recall what you remember and pass expected_minutes from it, and pass nothing when you remember nothing. Pass reads_per_hour only when the provider's documented rate limit or cost is tighter than the default.
5. Call start_watch with a title naming what it waits on, such as Deploy finished or Release run #46 passed, which shows as Watch "Deploy finished", the steps, and purpose: why the person wants it, in their words, such as get GitHub releases deploying through the webhook again. Every line the watch says measures what happened against it.
6. Tell the person what it answered: how long it usually takes and how long you will watch, its ceiling on reads, and anything it cannot follow and why. Then stop. Each milestone and the end come to the chat and their direct messages on their own: each job or step as it starts or passes, in one short line per check, the first one that fails at once with its reason, and a reading moves to running as soon as it shows the thing has begun.
7. When a step's read finds nothing to follow, such as a run that never shows up in its history or a first reading that is not the thing at all, the watch hands it back to you. Find a better read, try it once, and call repair_watch with the watch, the step, the new read and why the old one showed nothing, so the same watch follows it from here. When no read can show it, call repair_watch with give_up. Never start a second watch for the same thing.
8. A reading you take now beats what a watch remembers. When the person asks how it is going, read list_watches, which reads each watch that is still going again first. When a reading you took disagrees with what a watch or you said before, say so plainly and go by the fresh reading, and when it shows the watch follows the wrong thing, repair it. When they ask for longer, call extend_watch with the minutes in all, at most a day. When they ask to stop, call stop_watch.
