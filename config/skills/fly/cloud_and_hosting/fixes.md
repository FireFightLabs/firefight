---
name: fly_fixes
when: Writing or applying a fix to an app on Fly.io, such as a restart, a rollback to an earlier release, adding or removing machines, resizing them, starting or stopping them, or taking one machine out of traffic
tools: [rollback, restart, scale, scale_app, resize_app, start_app, stop_app, suspend_app, cordon_machine, uncordon_machine, recent_deploys, resource_status]
references: [deploy/rollback-guide.md, machines/machine-states.md]
---
A change goes through as one step of a fix, and each step says how to undo it.

1. Read what is there first. `resource_status` gives each machine's state and image, and `recent_deploys` each release's version, status and image. The undo comes from these values.
2. Pick the change:
   - Restart, for an app stuck in a bad state while its code is fine: `restart` on the app. Every running machine reboots on the image it already runs, one at a time, and stopped machines are left as they are. Nothing to undo.
   - Start, for an app that is down because its machines stopped or were suspended: `start_app` on the app, or on one `machine`. Each starts on the image it already runs, one at a time, and a suspended one resumes where it was when Fly can. Undo with `stop_app` on the machines it started.
   - Stop or suspend, for machines that should not run for now, such as a worker flooding a database: `stop_app` or `suspend_app` on the app, or on one `machine`. A stopped machine serves nothing. When its service has auto_start_machines on, Fly's proxy starts it again on the next request, so stop is no lasting fix there. Undo with `start_app`.
   - Cordon, for one machine that answers badly while the others are fine: `cordon_machine` with that `machine`. It keeps running, so its logs and state can still be read, while Fly's proxy sends it no requests. Undo with `uncordon_machine`. Never cordon every machine of an app, since nothing would serve it.
   - Roll back, when a release broke it: find the last release that worked with `recent_deploys`, then `rollback` with `to` set to its version, such as v41. Machines move to that release's image one at a time, each started again before the next. A machine that changed since it was read, such as during a deploy, or that does not start again, stops the rollback there, and the machines after it are left as they were and named, so check that machine before running it again. Undo by rolling back to the release that was serving before, the newest one `recent_deploys` showed. The app's settings, secrets and fly.toml do not go back, so a release that broke because of a setting needs that setting changed by a person instead. Fly's own release list does not show a rollback made this way, and the next deploy replaces it.
   - Scale, for an app with too few machines for its load, or too many: `scale` with `instances` sets how many machines it runs. New machines copy its newest machine and start one at a time, and extra ones are destroyed, stopped ones first. An app with more than one process group, such as app and worker, takes `scale_app` with the `group`. A machine with a volume is not copied, since each needs a volume of its own, so that is a step for a person with fly scale count. Undo by scaling back to the count `resource_status` showed before.
   - Resize, for machines too small for their load or running out of memory: `resize_app` with a `size` such as shared-cpu-2x or performance-2x, or `memory_mb`, for the whole app, one `group` or one `machine`. A running machine restarts on its new size, one at a time, and a stopped one is changed and left stopped. Memory has to fit the CPUs, which the refusal names. Undo by resizing back to the size and memory `resource_status` showed. Changing secrets stays a step for a person in Fly.io.
3. When the app is defined as code, such as fly.toml in a repository deployed by a pipeline, the lasting fix is a pull request to that code, since the next deploy would undo a change made here.
4. A refusal saying the token cannot make the change means it is a read-only token. Say so in the step, and keep the rest of the fix.
