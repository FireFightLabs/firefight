---
name: neon_changes
when: Finding what changed on a Neon project before something broke, or undoing a change to its data or computes, back to a snapshot, its parent or a moment
tools: [recent_deploys, run_history, list_branches, compare_database_schema, list_snapshots, rollback, restart, scale]
---
1. Call `recent_deploys` for the project, then for the branch. Operations name what Neon did and when: computes started, suspended or reconfigured, branches created, reset or restored. `run_history` with `run` reads one operation by its id, however old.
2. Call `list_branches` for when each branch was created and last changed. A branch reset from its parent, or restored, holds different data than the app expects.
3. Call `compare_database_schema` with `project_id`, `branch_id` and `database_name` to see how the branch's schema differs from its parent. A schema change applied to the default branch is the usual cause of new errors.
4. Call `list_snapshots` when the data itself has to go back. `rollback` on the branch with `to` a snapshot's id restores that snapshot onto it and moves its computes there, and with `to` parent resets it to its parent's current state. A branch other branches were made from keeps its current state as a new branch named like main-before-rollback-10111530, and its child branches move onto it, so say that branch will be kept. Both replace the branch's data and cannot be undone, and open connections drop, so say what will be lost before asking for it.
5. When no snapshot is close enough, `rollback` on the branch with `to` a moment just before the change, an ISO 8601 time with a zone such as 2026-10-20T14:30:00Z, or a Postgres LSN, restores the branch to its own state then. Its current state is always kept as a new branch named like main-before-rollback-10111530, its child branches move onto it, and its computes move onto the restored data, so open connections drop. The moment has to be within the project's history window, which depends on the plan. It needs a connection made with an organization API key. On a connection signed in through Neon's server, `rollback` says so, and the person connects Neon again with a key or restores in Neon's console.
6. A compute stuck in a bad state while its configuration is fine can be restarted with `restart`, which drops open connections. Say so before asking for it. `restart` on a suspended compute starts it instead.
7. A compute resized or given another autoscaling range shows as an apply config operation. `scale` with `plan` puts its size back, a size such as 2 or a range such as 0.25-4, and restarts it.
